== Purpose

Durable record of an AI design critique of the site's *architectural-dossier / broadsheet* direction.
Use this when revisiting layout, typography, motion, or brand hierarchy — not as a spec to implement wholesale.

== Context

The current site design was produced with an older AI model.
The overall look reads as an architectural dossier or broadsheet: stone neutrals, hairline rules, mono catalog labels, and near-zero border radius throughout.
That system is coherent, but it risks feeling interchangeable with other “serious architect portfolio” templates unless broken deliberately.

== What's working

Keep these as anchors when iterating:

* *Intentional type stack* — Space Grotesk (headings), Instrument Sans (body), Space Mono (labels) reads deliberate, not default.
* *Noise + frame atmosphere* — Poisson grain and the inset border frame add texture without purple-gradient or glow clichés.
* *Résumé main + sidebar* — Experience-first main column with a compact sidebar is clearer than an equal-card scroll layout.

== Highest-impact suggestions

Prioritize these when the next design pass has limited time.

=== 1. Give the first viewport a real visual

Photography is buried below the fold; the hero is mostly type on stone.
Pull a full-bleed or dominant urban/event photograph into the first viewport so the page could not belong to any other architect's portfolio.
The frame and noise can remain — let a strong image do the identity work upfront.

*Status:* _Done._ Full-bleed rainbow-crystal tapestry (stitched `frame_001|002|003`) with Lanczos WebP tiers (`1280` / `1920` / `2560`), `srcset`/`sizes="100vw"`, and theme-aware scrims; Photography section remains below.

=== 2. Cut the hero CTA row to two or three actions

`Browse work`, `Résumé`, `Philosophy`, `UI/UX`, `Inspirations`, and `Blog` in one row reads as a toolbar, not a focused entry point.
Keep primary paths (e.g. Browse work + Résumé) in the hero; move secondary destinations to footer, nav, or contextual links.

*Status:* _Open._ Six hero CTAs remain on the homepage.

=== 3. Decide the brand hierarchy: Ryan Johnson vs AMDphreak

`Ryan Johnson` at display scale vs `AMDphreak` as a tiny mono subtitle creates tension.
If AMDphreak is the public identity, elevate the handle — size, weight, or placement — so it is not visually subordinate to a legal name that may matter less on this hub.

*Status:* _Open._ Hierarchy unchanged: large name, small mono handle.

=== 4. Stop equal tiles — feature products; compact the org catalog

Product destinations deserve featured treatment with screenshots and hierarchy.
Forge/org destinations can collapse to a compact link list or catalog row instead of the same tile weight as flagship products.

*Status:* _Partially addressed._ Products use screenshot cards with `srcset` tiers and hover zoom; code orgs still use an equal grid of text tiles.

=== 5. Break the broadsheet monopoly

Vary visual weight across sections: not every block needs the same hairline rule + mono tagline + catalog code.
Reduce faux catalog chrome (`STR-XXXX`, `Ref. 8023`, `Capture_Engine / v2.0`) where it does not aid navigation.
Use fewer structural borders per section so emphasis means something.

*Status:* _Open._ Mono labels and reference codes remain in Experience, Projects, Photography, and section headers.

=== 6. One accent that is not stone

Introduce a single accent color drawn from photography or Memphis context — used sparingly on links, one CTA, or a key rule — so the palette is not exclusively stone/graphite.

*Status:* _Open._ Stone system dominates; Instagram icon gradient on the Photography CTA is the main exception.

=== 7. Sharpen the one-liner

Replace vague positioning (“visionary”, generic “built carefully”) with a concrete line: what you build, for whom, and what distinguishes the work (e.g. UX + DevX + ITIL + architecture for specific domains).

*Status:* _Partial._ Tagline now lists UX, DevX, ITIL, Architecture, RelyOps, DevOps; still ends with “a visionary.”

=== 8. Two or three intentional motions

Pick a small motion vocabulary and commit:

* Name or hero entrance on load
* Scroll reveal for one major section
* Stronger destination hover (beyond subtle underline)

Avoid sprinkling micro-animations everywhere; make a few moments memorable.

*Status:* _Partial._ Product and photography images use CSS scale on hover; no coordinated entrance or scroll reveal system.

== Hero tapestry & UI experiments (2026-07-25)

Session lessons (layout, frost, CTAs, GitHub menu traps) live in link:hero-tapestry-lessons.adoc[hero-tapestry-lessons.adoc].
Short version for this tracker:

* Stitched tapestry + resting Lanczos tiers (`1280` / `1920` / `2560`); see https://github.com/dev-centr/resting-lanczos[resting-lanczos].
* Avoid fixed-height + `object-cover`; keep tall hero + full-width vertically centered image.
* Frosted blur under the content cluster beat ever-heavier left/mid fades for CTA/social readability.
* Outline CTAs melted into the photo until frost (chips, then transparent borders again); social borders need stronger contrast on frost.
* GitHub menu “empty” was a mount gate (`open && menuPos`) + fragile ref — portal + native trigger fixed it; frost/flip layers need `pointer-events-none`.
* Tag `known-good-2026-07-25` before the next redesign spike.
